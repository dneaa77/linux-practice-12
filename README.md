## Вариант A

```bash
bash A/demo.sh
```
Скрипт создаёт отдельный временный каталог `demo.XXXXXX` внутри текущей папки и показывает результаты.

- `ls -li`: первое число — inode (номер записи метаданных файла в файловой системе); затем тип и права, количество жёстких ссылок, владелец, группа, размер в байтах и имя.
- `ln` создаёт второе имя того же inode. После создания число ссылок исходного файла становится 2. `ln -s` создаёт отдельный inode с путём к цели. После удаления оригинала жёсткая ссылка остаётся рабочей, количество ссылок становится 1. Символическая ссылка перестаёт работать, поскольку её путь больше не существует.
- `chmod u=rw,g=r,o=` задаёт права символически, `chmod 640` — численно: владелец читает и пишет (6), группа читает (4), остальные не имеют доступа (0). Скрипт проверяет чтение и запись от пользователя nobody. Если родительский каталог закрыт для nobody, отказ может быть связан и с его правами; для проверки именно файла запускать демонстрацию из доступного каталога, например `cd /tmp; bash /полный/путь/A/demo.sh`.
- `find . -type f -size +1048576c -mtime -1 -print`: поиск от текущего каталога, только обычные файлы, размер строго больше 1 МиБ (1048576 байт), изменение менее 24 часов назад, вывод путей. Созданный `large.bin` имеет логический размер 2 МиБ.

## Вариант B

### 1. Инкрементальный backup

```bash
mkdir -p test/source
printf 'first\n' > test/source/a.txt
chmod 640 test/source/a.txt
bash B/backup.sh backup test/source test/backup
bash B/backup.sh backup test/source test/backup
printf 'changed\n' >> test/source/a.txt
bash B/backup.sh backup test/source test/backup
bash B/backup.sh restore test/backup test/restored
cat test/restored/a.txt
ls -l test/restored/a.txt
cat backup.log
```
`rsync -a` сохраняет права, время и другие метаданные в пределах полномочий пользователя; `--checksum` сравнивает содержимое; `--itemize-changes` записывает изменения в журнал. Повторный запуск без изменения содержимого не передаёт данные файлов заново. Восстановление копирует резервную копию в указанный каталог. Удалённые из источника файлы сохраняются в backup (режим без --delete). Это одна актуальная резервная копия, а не история версий.

### 2. Дедупликация

```bash
mkdir -p test/duplicates
 dd if=/dev/urandom of=test/duplicates/a.bin bs=1K count=64 status=none
cp test/duplicates/a.bin test/duplicates/b.bin
python3 B/dedup.py test/duplicates
python3 B/dedup.py test/duplicates --apply
ls -li test/duplicates
```
SHA-256 группирует файлы по содержимому, затем программа дополнительно сравнивает байты. Учитываются файловая система, права и владельцы. По умолчанию только предварительный просмотр; `--apply` заменяет дубликат жёсткой ссылкой. Экономия оценивается по выделенным блокам старого inode (если у него не осталось других ссылок). После объединения запись в один файл изменит другой. Использовать только на тестовых данных без параллельных изменений; расширенные атрибуты и ACL не сравниваются.

### 3. Модель размещения блоков

```bash
python3 B/allocation.py
```
Модель: 16 блоков, заняты 3, 7, 11, 15; файл требует 4 блока. Свободно 12 блоков, но непрерывного участка из четырёх нет.

| Метод | Доступ к логическому блоку k (с нуля) | Фрагментация / накладные расходы |
|---|---|---|
| Непрерывный | 1 чтение | Внешняя фрагментация, трудное расширение |
| Связанный | k+1 чтений | Нет требования непрерывности; указатели и медленный случайный доступ |
| Индексный | 2 чтения без кэша | Дополнительный индексный блок; нет требования непрерывности |

Вывод: индексный способ удобнее для произвольного доступа при разрозненных свободных блоках. Последовательный доступ при непрерывном размещении обычно эффективнее. Числа — модель количества чтений, не измерение времени реального диска.

### 4. Исчерпание inode

```bash
bash B/inodes.sh
```
Скрипт создаёт временный образ 16 МиБ через dd, форматирует ext4 с малым числом inode (`mkfs.ext4 -N 128`), монтирует через `mount -o loop`, создаёт пустые файлы до отказа и выводит `df -i` и `df -h`. Ожидается `No space left on device` при 100% использования inode и наличии свободных блоков. Точное число файлов зависит от параметров ext4. Пустой файл занимает inode и запись каталога, даже если не содержит данных. Образ автоматически размонтируется и удаляется после опыта. Не запускайте mkfs на настоящем диске.

## Вариант C — FUSE с версионированием

Реализована плоская файловая система в оперативной памяти: create, open, read, write, truncate, unlink, readdir, getattr, utimens. При изменении непустого файла предыдущие данные сохраняются отдельным файлом `.v1`, `.v2` и т. д. Версии доступны на чтение, могут удаляться владельцем. Подкаталоги не реализованы; после размонтирования все данные исчезают.

Первый терминал (из папки проекта):

```bash
python3 -m venv .venv
.venv/bin/pip install -r C/requirements.txt
mkdir -p mountpoint
.venv/bin/python C/memoryfs.py mountpoint
```
Оставить процесс запущенным. Во втором терминале, в той же папке:

```bash
echo 'version one' > mountpoint/note.txt
cat mountpoint/note.txt
echo 'version two' > mountpoint/note.txt
ls -l mountpoint
cat mountpoint/note.txt
cat mountpoint/note.txt.v1
rm mountpoint/note.txt
ls -l mountpoint
fusermount3 -u mountpoint
```
Ожидается, что текущий файл содержит `version two`, а первая версия — `version one`. После удаления оригинала версия остаётся. Если fusermount3 отсутствует, использовать `fusermount -u mountpoint`. При ошибке `fuse: device not found` проверить `/dev/fuse` и поддержку FUSE системой; при ошибке `libfuse` проверить установку пакета libfuse2/libfuse2t64.

## Вывод
Жёсткие ссылки указывают на общий inode, символические — на путь. Права доступа ограничивают операции пользователей. Инкрементальная копия и дедупликация позволяют уменьшить объём повторно копируемых или хранимых данных. Исчерпание inode может препятствовать созданию файлов при наличии свободного места. FUSE позволяет реализовать файловую систему в пользовательском пространстве и расширить её версионированием.
